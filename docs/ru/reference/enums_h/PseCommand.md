## [Portal Solver Editor SDK](../../pse_sdk.md) > [Reference](../index.md) > [Enums.h](index.md) > [PseCommand]()

<br>

Перечисление `PseCommand` определяет уникальные идентификаторы команд для взаимодействия с **Portal: Solver**

Каждой команде соответствует строго регламентированная структура входных параметров (команда) и выходных данных (результат), передаваемых через объекты `PseData`

Правила чтения разметки:
- Маркер `[X]` в таблице указывает на точное смещение в байтах от начала данных
- Эти смещения напрямую используются в хелпер-функциях `pse::Data::set<X, T>()` и `pse::Data::get<X, T>()` для безопасного заполнения и чтения параметров
- Знак `-` означает, что команда не отправляет входные данные или не возвращает результат

## Архитектурные особенности

### Оптимизация булевых параметров _(`int8_t` вместо `bool`)_
В целях обеспечения строгой бинарной совместимости (**ABI compliance**) между различными компиляторами, языками (**C++, C#, Rust, Python**) и средами исполнения, все логические параметры (**флаги включения/выключения**) передаются через тип `int8_t` вместо стандартного `bool`:
- **Проблема встроенного `bool`:** В стандарте **C++** размер типа `bool` не зафиксирован жестко и может отличаться в зависимости от платформы и настроек компилятора, что недопустимо при прямой разметке **Shared Memory** по фиксированным смещениям
- **Соглашение о валидации:** Любое значение `bValue != 0` интерпретируется обработчиком игры как **`true`**, а `bValue == 0` наоборот строго эквивалентно **`false`**
- **Как это выражается в документации:** Если в названии переменной есть суффикс `b-` _(по венгерской нотации и стилю Unreal Engine)_, то значит его тип `int8_t` нужно интерпретировать так, как описано выше **^**

### Поведение переменных и регистров при смене класса _(Команда `PSE_COMMAND_ELEMENT_SET_CLASS`)_
Команда изменения класса элемента _(`PSE_COMMAND_ELEMENT_SET_CLASS`)_ **полностью** пересоздает элемент на в том же GUID, сохраняя **только:** GUID, Трансформацию и Видимость:
- **Полный сброс данных:** Старые значения всех регистров, State и Callback полностью стираются и сбрасываются в дефолтное значение для данного элемента. Новый элемент начинает работу с чистыми данными по умолчанию
- **Разная интерпретация:** Копирование данных между классами лишено смысла, так как каждый элемент интерпретирует одни и те же регистры по-разному. Именно поэтому их значения сбрасываются, да-бы для исключить логические ошибки
- **Сохранение данных через SDK:** Если данные старого элемента нужно перенести на новый, вы должны сделать это самостоятельно в коде своей программы: 
  - Получить текущее данные элемента _(`PSE_COMMAND_ELEMENT_GET_STATE` / `PSE_COMMAND_ELEMENT_GET_CALLBACK` / `PSE_COMMAND_ELEMENT_GET_ALL_REGISTERS` / `PSE_COMMAND_ELEMENT_GET_STATE_AND_CALLBACK_AND_ALL_REGISTERS`)_
  - Сменить класс элемента _(`PSE_COMMAND_ELEMENT_SET_CLASS`)_
  - Записать _(восстановить)_ данные элемента _(`PSE_COMMAND_ELEMENT_SET_STATE` / `PSE_COMMAND_ELEMENT_SET_CALLBACK` / `PSE_COMMAND_ELEMENT_SET_ALL_REGISTERS` / `PSE_COMMAND_ELEMENT_SET_STATE_AND_CALLBACK_AND_ALL_REGISTERS`)_
- **Но будьте осторожны:** Не забывайте сверяться с таблицей назначения регистров _(см. **[[Concept > Elements]](../../concept/elements.md)**)_ для элементов и проверять, какие именно данные вы переносите, так как для **двух разных элементов один и тот же регистр может кардинально отличаться по смыслу и логике работы**!
